# TOOLING

All commands: `python "<SKILL_DIR>/scripts/executor_tool.py" <command> ...`. Output is one JSON object on stdout (UTF-8).

## Exit Codes

- `0` — success.
- `1` — contract violation: invalid ledger transition, `plan-incomplete` (`ledger-init` on a plan that still carries plan-writing's writing marker), `plan-drift`, `settings-drift`, `settings-unavailable`, `dirty-worktree`, a refused `consent` (`consent-prod-write`, `consent-denied`, `consent-unknown-environment`), `run-diff` with `no-git` (not a git repository) or `run-diff-unavailable` (no finished unit), a refused `commit-run` (`no-git`, `baseline-head-unknown`, `index-not-empty`, `snapshots-missing`, `run-incomplete`, `failed-attempt`, `head-moved`, `mixed-files`, `foreign-changes`), `delegate-check` with `no-git` or a failed hook (`commit-failed`), git failure.
- `2` — input or filesystem problem: missing file or ledger, `no-units`, `duplicate-unit-id`, `unknown-dependency`, dependency cycle, `exec-dir-inside-workdir`, `checkpoint-restore --paths` with `unknown-path` (neither in the snapshot nor in the working tree; nothing is restored), `invalid-path` (absolute, `..`, drive-relative such as `C:x`, or git pathspec magic starting with `:`) or `paths-empty` (nothing left after excluding `BACKLOG.md` and the chain files; nothing is restored), `run-diff --include-fixes` with a journal error (`journal-missing`, `journal-corrupt`, `journal-plan-unknown`, `journal-unavailable`, `invalid-path` for a bad `fix_files` entry) or without `--markdown` (`include-fixes-needs-markdown`), `commit-run` with `bad-subject` (the subject is not `<type>(<scope>): <subject>` of at most 72 characters), `ledger-path` with `ledger-ambiguous` (both the plan's and its roadmap's ledger exist; the error names both paths), `ledger-init --light` or `unit-finish --delegated` with an empty model (`light-invalid`, `delegated-invalid`), `delegate-check` with `snapshot-invalid` (unreadable, not a snapshot, taken in another repository) or with `--files` next to `--snapshot-out`.

Errors print `{"ok": false, "errors": ["..."]}`; `plan-drift` also carries `added` and `removed` unit ids, `settings-drift` carries `changed_keys` and `settings_source`, `settings-unavailable` carries `settings_errors`, `index-not-empty` carries `staged`, `failed-attempt`, `mixed-files` and `foreign-changes` carry `files`, `run-incomplete` carries `units` (id and status), `head-moved` carries `baseline_head` and `head`.

## Loop Commands

| Command | Purpose |
|---|---|
| `ledger-init <exec_dir\|auto> <plan> [--workdir R] [--whole] [--allow-dirty] [--accept-drift] [--allow-temp] [--light M]` | Create or resume the ledger; `--light M` stores `settings.light` (the model of the green units this launch delegates; a launch without it removes the key); baseline snapshot of `R`; the result carries the absolute `exec_dir`. For a roadmap: units `task-<id>` of each part (field `part`) and a checkpoint `part-<id>-done` per part; `warnings` gets `part-without-tasks: <id>` and `part-without-criteria: <id>`. `dirty-worktree` ignores `BACKLOG.md`, the run's chain journal and the pipeline's own files by name (GATE.md, Foreign Changes), not another `*-chain.json` |
| `unit-begin <exec_dir>` | Next unit + `strategy` (`isolation`, `model_depth`, `gate_tier`, `delegable`: light, main, not a checkpoint, no `External`) + its `text`, `files`, `external` entries (`env`, `access`, `kind`, `consent`, `confirmed`, `source`; recorded on the unit) and `foreign_changes` (`null` + `foreign_warning` when the check is off); marks it `running`. Files changed outside the run since the last unit → `reason: foreign-changes` with `foreign_changes`, `expected_tree`, `current_tree`, nothing marked |
| `consent <exec_dir> <env> read\|write` | Run-scope consent the engineer gave; refused for prod `write`, for `deny` and for an environment not in the settings |
| `accept-changes <exec_dir> [--note N]` | Keep the foreign changes: `expected_tree` = current tree, event in `foreign_events` |
| `unit-finish <exec_dir> <unit> pass\|fail [--error S] [--note N]… [--delegated M]` | Snapshot + done, or failed + `decision`/`restore_to`. `--delegated M`: a subagent on `M` made this attempt; records `units[].delegated` (kept by later attempts) and `delegated` in the journal's `unit-finish` event. `--note` is repeatable: one note per agreed deviation and per External entry confirmed for this task only; each lands as its own `units[].notes` element |
| `delegate-check <repo> --snapshot-out F` / `delegate-check <repo> --snapshot F --files P…` | Delegated units (EXECUTION-STRATEGY.md, Delegation). `--snapshot-out` writes the snapshot `F`: `git status --porcelain=v1 --untracked-files=all --no-renames`, the `hash-object` of every listed path and the repository root after `realpath` (`F` itself is left out). `--snapshot` compares the working tree with `F` and the named paths `P`: `verdict` `pass`/`fail`, `outside` (named, outside the root after `realpath`/`normcase`), `unreported` (changed, not named; unnamed pipeline files by name, GATE.md, Foreign Changes, are left out), `phantom` (named, not changed), `changed` |
| `run-diff <exec_dir> [--markdown FILE [--include-fixes JOURNAL]]` | Files and `--stat` of what the run changed: baseline snapshot vs last unit snapshot. `--markdown` writes the diff report `FILE` (summary table, one `diff` block per file, pipeline artifacts left out — `BACKLOG.md`, the run's journal and the chain-file names of GATE.md, Foreign Changes, in the run's plan folder only — and listed in the section "Not included (pipeline artifacts)" / «Не включены (артефакты конвейера)»; audit fix files git ignores under "Not included (ignored by git)" / «Не включены (игнорируются git)»; the user's git config (colour, prefixes, external diff, textconv) does not change it) and returns `path`, `files`, `excluded`, `fix_files`, `ignored`; `--include-fixes` adds the audit's `fix_files` from the journal, diffed against the working tree. Not a git repository → `no-git`; no finished unit → `run-diff-unavailable` |
| `checkpoint-restore <repo> <sha> [--paths F …] [--exec-dir D]` | Restore the working tree, or only the files `F`, to a snapshot or tree (confirmation required); `--exec-dir` moves `expected_tree` to the restored tree and records `--paths` restores. The executor always passes `--exec-dir`. `F` are relative to the repository root (as in `foreign_changes`), whatever `--workdir` the ledger has; each path in the result carries its status, `unchanged` when the file already equals the snapshot. The pipeline's own files (`BACKLOG.md` at the root; the run's own journal and its lock wherever they lie; by name in the plan folder of the run given by `--exec-dir`, in any folder without it, `*-chain.json` and its lock, specs, plans, parts, roadmaps, completion, review and report files, `*-diffs.md`, `*-followups.json`) are never restored: a full restore leaves them as they are and `--paths` drops them |
| `checkpoint-prune <exec_dir> [--workdir R]` | Delete this run's `refs/plan-executor/<run>/*` |

## Commit Commands

Used only by the COMMIT stage (`/plan-executor <plan> commit`, WORKFLOW.md, COMMIT).

| Command | Purpose |
|---|---|
| `ledger-path <plan> --workdir R` | Read only: the `exec_dir` of this plan's ledger (the same path as `ledger-init auto`), `exists` and `matched`. For `<X>.md` with a `<X>-roadmap.md` beside it, it checks the ledgers of both (for a roadmap, also its master plan's) and returns the existing one, `matched: plan` or `roadmap` (`null` when none exists); both exist → exit 2 `ledger-ambiguous`. Changes nothing, clears no consents, checks no settings drift |
| `commit-run <exec_dir> --message-file F [--journal J]` | Commit the run's files plus the audit's `fix_files`, minus the pipeline artifacts and the files already committed, with the repository's hooks. Before writing anything it checks, in this order, and stops at the first failure: `no-git`, `baseline-head-unknown` (a ledger without `baseline_head`), `index-not-empty`, `snapshots-missing` (the run's snapshots were pruned and garbage-collected; only the expected tree missing → `accept-changes` resets it), `run-incomplete` (a unit is still `running`), `failed-attempt` (a unit is `failed` and not rolled back: files of the commit set that differ from the last done snapshot and are not audit fixes, field `files`), `head-moved` (`baseline_head` is not an ancestor of `HEAD`), `mixed-files` (uncommitted work before the run that the run then changed), `foreign-changes` (changed after the last unit, not an audit fix); then an empty set gives `empty: true`; then `bad-subject`. A failed hook restores the index (`commit-failed`). Success: `sha`, `subject`, `files`, `excluded` (run files left out as pipeline artifacts), `excluded_outside_chain` (a `*-chain.json` in the plan's folder other than the run's journal: left out by its name, though it may be a project file), `incomplete` (units `failed` or `pending`: a warning, not a refusal), `backlog` (`section`, `appended`, `exists`, only when there are deviations: the plan header's `**Deviations from spec:**` items and the units' notes except `subagent-unavailable` and the `External:` confirmations (`plan_deviations`), appended once to the goal's `BACKLOG.md` section as `amend spec <spec>: <gist>` through `brainstorm_tool.backlog_append`; an item already open there is `exists`) and `warnings` (`backlog-unavailable`, `backlog-write-failed`: the commit is made); with a journal (`--journal` or the ledger's `journal`) the commit is recorded in `stages.commit.artifacts.commits`. Never `--no-verify`, `--amend`, `push` or `--force` |

## Low-Level Commands

`detect-input`, `detect-lang <plan>`, `parse-roadmap`, `parse-tasks`, `ledger-next`, `ledger-mark`, `ledger-status`, `checkpoint-detect`, `checkpoint-create <repo> <label> [--run-id]`, `recommend-strategy`, `recommend-gate`, `scope-context`, `render-progress`. They exist for debugging and manual recovery; the loop above covers normal execution.

## Ledger

Schema: `assets/ledger.schema.json` (version 2: `source_sha256`, `run_id`, `workdir`, `baseline_checkpoint`, `baseline_head` (the `HEAD` of the first `ledger-init`; an older ledger has none and `commit-run` refuses it with `baseline-head-unknown`), `expected_tree`, `foreign_events`, `settings`, `settings_source`, `consents`, `journal` (`{path, plan}` of the chain journal or `null`), per-unit `source`, `notes`, `external`, the optional `part` of a roadmap unit and the optional `delegated`; `settings.light` of the last launch). Version 1 ledgers are migrated on load; a ledger without `expected_tree` starts the check after its next `unit-finish`. `ledger-init` also prints `warnings` (not stored).
